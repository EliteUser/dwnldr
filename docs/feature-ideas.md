# dwnldr — идеи фич (обсуждение, без реализации)

## Context

Приложение: SC/YouTube → MP3 (Express + yt-dlp + node-id3 + sharp, React/Mantine, PWA). Без БД; «синк» — скан имён файлов через File System Access.
Ограничения: без платных/ключевых API, без AI, без БД. Библиотека на телефоне и на ПК.

**Настоящая задача (уточнено):** сотни mp3 уже с нормальными именами. Для каждого нужна обложка, понимание «есть ли вокал» и lyrics. Узкое место — **не UI правки, а ручная проверка** каждого результата. Таблица или «по одному» — та же работа. Значит, ценность только у того, что **убирает проверку** для большинства треков.

---

## Часть 2 (главное). Как убрать ручную проверку

### Принцип: проверять только то, в чём не уверены

Совпадение проверяется не глазами, а **сигналами, которые машина сверяет сама**:

- **длительность файла ± 2 сек** с длительностью кандидата — самый сильный дешёвый сигнал (разные версии/ремиксы почти всегда отличаются по длине);
- **нормализованное «artist – title»** совпадает точно (эвристики уже есть в `packages/client/src/utils/match-track.ts`);
- **источник = аккаунт артиста** (у SC uploader совпадает с artist).

Все три совпали → применяем **без показа**. Это ожидаемо большинство треков, если библиотека изначально с SoundCloud/YouTube.

### Три корзины вместо очереди

1. **Уверенно** → записали теги автоматически, отчёт «N готово».
2. **Сомнительно** (имя совпало, длительность нет / несколько кандидатов) → **сетка обложек**, а не таблица: 30–50 превью на экране, неправильные видны боковым зрением, тап — заменить на следующего кандидата. Проверка десятков за минуту, а не по треку.
3. **Не найдено** → опционально **сгенерированная обложка** (имя артиста на цветном фоне, детерминированный цвет от хеша, делается sharp’ом). Убирает «пустые квадраты» без поиска вовсе.

### Обложки (без новых интеграций)

- SoundCloud search тем же scraped client_id (`packages/server/src/services/soundcloud.ts`) → `artwork_url` в `-original` / `-t500x500`, `duration`, `user`.
- yt-dlp `ytsearch3:` / `scsearch3:` `--flat-playlist --dump-single-json` → thumbnails + duration. 16:9 превью → центр-кроп + `sharp.trim()` для чёрных полей (`saveCover` в `packages/server/src/services/track-pipeline.ts`).

### Lyrics и «есть ли вокал» — честно

- Без внешнего источника текстов **не получить**, а детект вокала по аудио без ML нереален.
- Единственный адекватный вариант: **LRCLIB** (lrclib.net) — бесплатный, без ключа и регистрации, open-source. Эндпоинт `/api/get?artist_name&track_name&duration` отдаёт результат **только при совпадении длительности ±2 сек** → совпадение уже проверено, глазами смотреть не нужно. Отдаёт `plainLyrics`, `syncedLyrics` и **флаг `instrumental`** — это и есть ответ «есть ли текст».
- Нет в LRCLIB → lyrics пусто, вокал «неизвестно»; не пытаемся угадывать. Помощь глазу: подсказки из имени (`Instrumental`, `Inst.`, `Dub`, `Mix`) только как пометка.
- Это **единственная новая интеграция** в плане; без неё пункт про lyrics отпадает, остальное работает.

### Без БД

Теги в файлах = состояние. Повторный скан читает ID3; трек «готов», если есть APIC (+ USLT или TXXX `dwnldr:instrumental` / `dwnldr:nolyrics`, чтобы ненайденные не искались каждый раз заново).

### Поток (один экран)

Выбрать папку (handle из `packages/client/src/utils/folder.ts`, `readwrite`) → «Обработать» → прогресс → итог: «412 готово, 38 на проверку (сетка), 27 не найдено». Запись тегов: в браузере (`browser-id3-writer`) или через существующий `writeTags`, обратно в тот же файл `FileSystemWritableFileStream`.

### Риски

- Android Chrome: запись в выбранную папку работает не везде — проверить на устройстве первым делом; fallback — прогонять библиотеку на ПК и копировать.
- yt-dlp очередь одна → сначала SC API (быстро), yt-dlp только как фоллбэк.
- Ремиксы/бутлеги, которых нет ни в SC, ни в LRCLIB, останутся в корзинах 2–3 — это нормально.

## Часть 1. Общие фичи (кратко)

Batch-загрузка сетов/плейлистов и «всех недостающих лайков» (матчер уже есть) · шаблон имени файла · формат m4a/opus без перекодирования · `loudnorm` и обрезка тишины · trim по времени · SponsorBlock `music_offtopic` через yt-dlp · `--split-chapters` для миксов · видео mp4 · поиск дубликатов · one-tap скачивание из Share Target · **LRCLIB и авто-кроп обложек для новых скачиваний тоже** — чтобы библиотека больше не портилась.

## Verification (если дойдёт до реализации)

Выборка ~50 реальных треков → посчитать долю корзины 1 и вручную проверить, что в ней 0 ошибок (если ошибки есть — ужесточить порог). Цель: корзина 1 ≥ 70%, ошибок в ней нет.
